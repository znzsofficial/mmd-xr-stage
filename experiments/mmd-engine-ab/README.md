# 单角色引擎 A/B：现有舞台运行时 vs Babylon MMD

这是单独的本机实验，不是上线的替代渲染器。当前组调用项目的 `createMmdRuntimeHandle`；候选组用 Babylon.js 9.15.0、`babylon-mmd` 1.3.0、单线程发行版 WASM、立即求值及其集成 Bullet。两组都做实际 WebGL 绘制，页面结束时保留同一动作时刻的并排画面。

## 在项目根目录复跑

先按主项目要求安装依赖（Node 26.12.1、pnpm）。实验自身使用单独的 npm 锁文件：

```sh
npm --prefix experiments/mmd-engine-ab ci --ignore-scripts
node experiments/mmd-engine-ab/serve.mjs
```

打开 `http://127.0.0.1:4286`，选本地模型目录、PMX 和至少 8 秒的身体 VMD，点开始。样本应有动态刚体骨和动作驱动的腕骨；这是为了拒绝拿静止模型或空物理比较。每次复测建议刷新页面。本机只分发实验程序和自带 WASM，浏览器直接读取你选择的文件；结果不含文件名或路径。实验构建输出在此目录的 `dist/`，不写项目的 `dist/`。

## 怎么测的

- 同一浏览器页面、同一份 PMX、配套纹理、身体动作和姿态时间，两边都使用模型原始尺寸。比较 400×400、同视角、单眼的空背景；不开 AA、实时阴影、XR、手部碰撞或项目专属的胸部受压。渲染保留两套运行时各自的 MMD shader、描边、材质与显示处理，不代表像素等价。
- 固定每步 1/72 秒。每种物理状态重新加载两个模型；先预热 96 帧，再测 16 对窗口，每窗口 24 帧，两套引擎轮流先跑。结果是**每个窗口内单次更新均值的中位数**。CPU 角色更新不含绘制、加载、绑动作或 GPU；开关物理的构造过程不计时。物理使用双方各自的 Bullet 实现，不要求布料轨迹逐点相同。
- 记录骨数、带漫反射贴图的材质数、腕骨位置变化；在相同帧号逐一比较**同一引擎**的开／关物理动态骨位置，确认开物理不是空操作。
- 单独固定最后一帧，预热绘制后交替测 8 对窗口，每窗口连绘 4 次，前后做同步像素读回。这是单眼空场、含同步的绘制墙钟时间，不能与 CPU 列相加推算头显 FPS。截图在用户浏览器内，可目视检查脸、头发、透明和服装。

## 桌面结果（2026-11-20）

Edge 157.0.4341.60，ANGLE/SwiftShader 软件 WebGL，三次新页面。两个运行时都加载 505 根骨、21 个带漫反射贴图的材质；有 317 个可匹配的动态刚体骨。手腕确实随动作移动，在两套实现中开／关物理均产生非零的动态骨轨迹差；无加载或渲染报错。

| 每次更新中位数（毫秒） | Three/当前：第 1、2、3 轮 | Babylon MMD：第 1、2、3 轮 |
|---|---|---|
| 角色，关物理 | 0.685、0.717、0.702 | 0.050、0.050、0.050 |
| 角色，开物理 | 2.110、2.465、2.144 | 1.140、1.319、1.192 |
| 单独绘制最后姿态，开物理组 | 17.975、17.225、17.712 | 8.162、7.975、8.275 |

**结论：值得在 Quest 上做下一步实测，还不构成迁移依据。** 对这一份 PMX/VMD，开物理组三轮均为 Babylon 的 16 个更新窗口全部更短。候选画面服装和皮肤偏暗、脸部受光不同；较短的绘制时间不是同画质的证明。未测试产品完整教室、双眼 XR、真实 GPU、暂停拨衣与手感、切景恢复、包下载／启动或其他模型。本实验没有比较 Rapier 或球面移动。若继续，先统一两边材质观感和头显分辨率，再用同角色、同动作做可交互的双眼对照。
