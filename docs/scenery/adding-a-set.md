# 新布景从哪里接入

两种选择看的是**切门时是否需要换掉整个活动分区**。医院的门诊、手术室和女卫生间共用楼层、角色名额和布局，房门就是墙上的真实开口。教室和草坪则各自存布局；走过连廊要释放上一侧的角色和 Bullet，再恢复另一侧。

## 在现有区域里加一个房间

在该景的布局文件中定义墙段、门洞和不可站立的家具。渲染、合法落点和摇杆通行规则读取同一套坐标。屏幕机位应落在能走到的位置，朝向房间里可辨认的设施。这个房间不需要新 `SceneryId`，也不应触发回场恢复。

## 新增独立区域

1. 在 `scenery/catalog.ts` 加 ID、名称键和中英文翻译。准备页、VR 选景、屏幕选景、分景布局及报告使用该 ID。
2. 在本景目录编写布局与模型组件，将组件登记在 `scenery/roomSets.tsx`。组件只在所属区域挂载；准备页的目录不依赖模型组件。全景共享的地面拾取、角色和物理生命周期仍由舞台持有。
3. 在 `placementAreas.ts` 接入落点规则，确保 `(0,0)` 能用于「放在中央」。在 `roomViews.ts` 登记屏幕入口机位及本景导览。机位切换不加载房间，也不移动角色。

   有楼梯或戏台时要单独核对高度：参见[秦淮歌楼](./qinhuai.md)。拾取平面、目标世界坐标和摇杆行走高度分别使用同一布局；房间高度和玩家手调高度不可相互覆盖。楼上放下角色后切景往返，要验恢复后的实际 `y`，不能只数角色个数。
4. **两个独立区要步行相通时**，在 `connections.ts` 添加两条有向记录。每条定义出发地、目的地、出发地坐标内的门线及有效宽度、XR 原点平移量、屏幕到达机位。两向门线错开，避免原地反跳；不同出口可同属一个区域。屏幕导览从同一记录生成跳转，不能靠「第几个机位」决定是否过门。需要限制脚下通行时，把入口、足点与摇杆移动函数登记在 `walkSurfaces.ts`。从菜单切景用入口；过门则保留头向和追踪偏移，把上次摇杆原点移到新坐标系，避免下一帧从旧位置扫墙。

验收分别走一次屏幕和模拟 XR：门线之外不误切、正反向通过且方向连续、放置中的布景不自动切走、远端可实际放置、家具不接收、回区后仍是本区角色与动作。性能报告中的 `roomRestores[]` 只用于离区重建，不把同楼层走进一间房记成恢复。
