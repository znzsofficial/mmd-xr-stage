# 双喜堂 · 江南喜院

[巷口看门楼与花轿](../screenshots/wedding-court-entry.webp) · [门内看轿帘织锦](../screenshots/wedding-bridal-sedan.webp) · [喜堂与婚联](../screenshots/wedding-ceremony.webp) · [妆台](../screenshots/wedding-vanity.webp)

从巷口花轿旁穿过门楼，走影壁右边的空地，两侧宴桌之间就是正堂。想拍两位角色，把他们并肩摆在礼案前，然后在屏幕的「游览机位」选「宾席望喜堂」或「正堂礼案」。不需要婚礼动作。面向礼案，右手的侧门通整妆间；镜子前能放第三个角色，回身能透过门洞看喜堂。

**回望有两个不同的镜头。** 从堂前东侧看出去，透过院门能看到花轿侧面和轿旁的人，西侧门垛挡住一部分轿帘。要看正面帘纹，走到南门内再回头。这里是一座受江南民居启发的虚构喜院。

## 空间和落点

- 院落和喜堂共用同一层地面。巷口在南（`+Z`），XR 起点 `(0.65, 10.15)`；南门净宽 3.2 米。喜堂前的双人空地为 3 × 2 米，建议脚位 `(−0.75, −4.98)` 和 `(0.75, −4.98)`。天井中央 `(0, 0)` 是屏幕「放在中央」的落点。
- 从花轿到喜堂再到侧室都保持同一场景和角色布局。相机能看过矮桌，但背包准星不能穿过墙、门扇、影壁和屏风放人。花轿旁和妆台前各有空地，摆过角色后仍能沿原路走回来。
- [布局](../../src/mmdVrShowcase/scenery/wedding/weddingLayout.ts)同时给建模、手柄步行、放置和导览提供墙柱、陈设与尺寸。[建筑](../../src/mmdVrShowcase/scenery/wedding/WeddingCourt.tsx)和[家具](../../src/mmdVrShowcase/scenery/wedding/furnishings.tsx)只在喜院活动时挂载。

## 实放与回访

在屏幕用鼠标、在模拟 Quest 3 用摇杆与右扳机各走了一遍：两份独立 PMX（各高 1.726 米）摆在礼案前，间距 1.50 米。到东侧室把 GLB 放在妆台前 `(8.62, 0, −5.77)`；从实体墙另一侧点同一坐标会被拒绝，扳机从屏风后指过去也被拒绝。到侧室远端回望，视线经过侧门。在两种模式下，切去简易地台时三个节点都卸载，回来是新建的两个角色与一个物件，原位置和朝向一致。

轿帘的两种织锦、瓷碗青花、喜字剪纸与漆盒梅鹊共用一张[陈设图集](../../src/mmdVrShowcase/scenery/wedding/wedding-furnishings.webp)（1536 × 1024，232,000 字节）。[烘焙源](../../src/mmdVrShowcase/scenery/wedding/furnishingsBake.py)可从头重画。故意延迟这张图时，轿帘先显示朱红底色，再在本次进场中换成织锦；无需切走重进。上面是产品 WebGL 和模拟输入的检查，Quest 真机帧率、佩戴舒适度另验。

门额、瓦当和竖写婚联使用 [2048² 建筑图集](../../src/mmdVrShowcase/scenery/wedding/architecture-jiangnan.webp)（200,986 字节），桂树枝叶使用 512² 图（65,910 字节），两者均由[建筑烘焙脚本](../../src/mmdVrShowcase/scenery/wedding/architectureBake.py)绘制。按空间拆分屋群后，妆台机位从初版 98,118 个三角形降至 26,164 个，绘制从 7 次变为 9 次；最终入口为 23 次／112,092 个三角形。桌面空场依次游览喜院、医院、草坪、歌楼，三轮回来入口均为 20 份几何、5 份纹理；208 次 WebGL 着色器编译没有失败。
