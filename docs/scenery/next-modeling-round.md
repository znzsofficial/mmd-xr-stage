# 已完成的建模计划：中式婚礼喜院、草坪通医院、秦淮近景与本地音乐

**归档状态：本轮交付已于 `77d561c` 上线。** [喜院](./wedding-court.md)、[门诊步道](./clinic-garden.md)、[秦淮琴案与系舟处](./qinhuai.md)和[单曲音乐](../gameplay/README.md#上手与验收)均可使用。下文保留原分工与验收设计；文末的新景仍是候选，不是待派工任务。最新工作从[短交接](../HANDOFF.md)接手。

## 主景：花轿进门，穿院入喜堂

建议做一座**江南民居式喜院**（暂名「双喜堂」，建议独立 ID `weddingCourt`）。秦淮歌楼让人从楼上看台上的演员；喜院的中心是两个人并肩站在堂前，门外、院中、席边都能看见他们。视觉参考民俗陈设，不宣称复原某一朝代或地区的一套标准婚仪。

| 走到哪里 | 角色怎么摆，镜头看什么 | 需要实做的细节 |
|---|---|---|
| 巷口迎亲 | 一位角色站花轿旁，从门内回望能同时看到人和轿 | 做出轿杆离地的高度、抬杆绑绳、掀起的轿帘与踏脚；轿杆也有占地，不能穿过去放人。 |
| 天井入席 | 从影壁旁转入院子，沿两侧宴桌间的通路前进；从宾席斜看堂前双人全身 | 石板、灰瓦和木柱保留原色，红绸集中在门楣和礼案。席面近处做瓷盏、筷架和碗碟叠放的厚度，中央通路留空。 |
| 正堂行礼 | 礼案前并排放两位自选角色；从院中拍正面，侧廊拍半身 | 成对椅、礼案、双喜剪纸、烛台。留独立的脸部照明，不让背后的红墙、烛焰或悬匾淹没人脸。首版用静态陈设，不要求角色自带拜堂动作。 |
| 侧室整妆 | 从侧门到妆台旁放一个角色，再转身透过门洞看回喜堂 | 铜镜、梳篦、漆盒和窗上的剪纸；铜镜先用有色金属表现，不开实时反射相机。门扇和屏风真挡射线。 |

**第一步是摆两个人的灰模，不是画喜字。** 初版约定：礼案前的双人空地以 **3 × 2 米**为起点；主通路净宽约 **1.5 米**。把 `(0,0)` 留作「放在中央」的合法位置。第一版全程同层，可步行到每个取景点；同一场景不因跨院门或进侧室而卸载角色。门口回望、宾席斜看双人、梳妆台近看，是优先保留的三个镜头。尺寸是设计起点，实际用两名角色走位后可调。

## 哪些现有场景值得先改

**首选：晴空草坪 ↔ 医院候诊厅。** 草坪已有教学楼连廊和泳池门廊，是三个目的地共用的起点。建议从花径分出一条有方向牌的步道，绕过矮花池，走到门诊雨棚，再进候诊走廊。门外留出两处有用的站位：在雨棚旁摆人，从花径拍到门牌与全身；从候诊厅向外看，门洞框住另一位角色和花园。这样从教室或泳池出发也能经草坪步行到医院。

- **真门洞。** 改造前，[医院布局](../../src/mmdVrShowcase/scenery/clinic/clinicLayout.ts)在 `z=4.8` 的南墙整段封闭，行走和放置均受外墙矩形限制。沿候诊走廊中轴 `x≈0` 开南门，把门洞、门外铺装和雨棚柱脚写进共享布局，让墙体、射线和可走地面读同一份数据。诊室等内门维持同层通行。
- **双向过门。** 先用灰模定花径岔口，避开现有教室／泳池门线、纸鸢站、树丘和围栏。草坪侧能看见门诊入口轮廓，医院侧能看见门外花径；只挂载当前区。在[连接表](../../src/mmdVrShowcase/scenery/connections.ts)增加 `lawn → clinic` 与 `clinic → lawn`，两条门线前后错开；XR 保留头向，屏幕导览读取同一出口数据。医院和草坪仍分别保存角色与动作。

**第二处：秦淮歌楼琴案与系舟处。** [登楼看戏](./qinhuai.md)的路线已通，值得补的是手边的细节。从[琴案](../screenshots/qinhuai-music.webp)看琴身弧度、弦枕与桌缘；从[画舫](../screenshots/qinhuai-river.webp)看缆绳怎样绕桩、石驳岸哪里积下水痕。琴身和绳结保留轮廓，细纹进贴图。现有楼高、落点、水域拒放按原机位回归。

**下一处候选：星环遗庭的远端观星台。** 桥和露台已经可走、可摆角色，适合补铜仪刻线、氧化铜斑和手边的星图，让玩家走到尽头后有东西可近看。本轮先把医院支路和歌楼做完。

## 本轮附带：单曲本地音乐

准备页可选一首本地音频；进场后在屏幕控件或 VR 菜单手动播放、暂停、调音量。静止摆人也能听；音乐独立于 VMD，切景不重新开始，退出观看即停止，换文件或清除时释放旧音源。无音频照常进场，不自动播放或提示补文件。

验收用桌面短音频实测播放／暂停、音量、跨景续播和退出停声；模拟 XR 验菜单操作，并验不选文件也能进入和退出。无需为此往 Quest 拷歌。

## 合入门槛

- **能走、能摆、能回望**：喜院用两名角色和一件物件验证堂前并排、妆台旁放置、隔屏拒放；歌楼复测上楼与楼上恢复。用实际屏幕鼠标／模拟 XR 扳机射线验落点。
- **医院支路走一圈**：草坪花径与医院候诊厅各留一位角色。模拟 XR 从花径走进候诊厅再按原路返回，屏幕导览也走双向；检查门口不反跳、门外侧擦过不切景、放置中不过区。雨棚下可摆，柱脚和隔墙拒放；回访两区后各自位置与动作正确。再走原有教室↔草坪↔泳池，医院三个内门仍能通行且不触发跨区恢复。
- **实景可比**：每处交一张带尺度参照的内部验证画面，公开画廊只用可公开的实景。旧景固定镜头、灯光、阴影和画质重拍；婚礼至少交入口回望、堂前双人构图、侧室近景。以脸部可读、衣服不融进背景、桌脚和轿杆不悬空为准。
- **性能单列**：记录同机位的绘制调用、三角形、纹理；反复切出再返回，查几何/纹理是否持续增长。Shader 在真实 WebGL 编译出图；桌面模拟不换算成 Quest FPS。各组先跑专项，主代理统一类型检查、全测、构建、模拟 XR 和生产资源校验。真机近看舒适度下次自然游玩时再验。

## 婚礼之后的新景候选（未排期）

- **首推海边终点站**：站房檐下、站台尽头、通向海堤的步道共享海平线。搪瓷站牌旁拍全身，长椅边拍侧脸，从堤上回望站灯；与喜院的内向围合形成反差。先做安全站位和海风感，列车经过留作可选效果。
- **雨夜唱片行**：街边橱窗、试听位、收银台形成三段两三步可达的近景。雨玻璃和封套适合拍近景；不依赖背景音乐功能。
- **旧城皮影台**：在幕前看角色与影子，绕到幕后看灯架和皮影实体。先用一段绢幕验证透明发梢与剪影在双眼里是否稳定，再决定是否扩成完整院落。
