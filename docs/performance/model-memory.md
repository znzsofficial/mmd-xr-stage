# 角色在场时的形态纹理与收回物件后的残留

基线：`dbd2e96`，Three r187、官方 MMD loader 0.8.6 加现有补丁。一个问题发生在角色**还在场上**，另一个发生在 glTF 物件**已经收回**。测的是实际 WebGL 资源申请／删除；不等于驱动的物理驻留量，也不是 Quest 帧率测试。

## 形态数据：同一演员只为相同几何申请一份

参考角色 A 有 52 个顶点形态、30,653 个顶点。1 个主网格、21 个材质绘制和 13 个描边原本指向相同数据，却各持一个几何对象。r187 按几何对象缓存形态数组纹理，导致每个对象都申请一份 26 MiB 的 `RGBA32F`。现在[在第一次 GPU 上传前](../../src/mmdVrShowcase/stage/loading/shareMorphGeometry.ts)核对骨架、索引、属性与形态数组身份，只在同一演员内共享真正相同的源几何。

| 场景状态 | 旧版形态纹理 | 新版形态纹理 |
|---|---:|---:|
| 空场 | 0 | 0 |
| 放入 A | 35 份 / 910 MiB | 1 份 / 26 MiB |
| 两个相同的 A 实例 | 70 份 / 1,820 MiB | 2 份 / 52 MiB |
| 移除第一个，第二个留场 | 35 份 / 910 MiB | 1 份 / 26 MiB |
| 移除最后一个 | 0 | 0 |

在不带布景、关闭阴影的对照中，同一演员全部已计价纹理合计 **983.93→99.93 MiB**。其中的 884 MiB 差值全部来自形态数组；没有缩小原始贴图或删掉表情。只让第一个实例眨眼，第二个与最初站姿逐像素相同；移除第一个，第二个的纹理和画面仍在。正式构建里从背包把 A 放在教室，去空泳池再回教室两轮：形态纹理每次都是 **26→0→26 MiB**；在教室点「收回背包」后形态分配归零，教室的几何和纹理总数回到空场值。

另一个原衣角色 S 的 loader 确实拆出了 **38 个身体几何**，不是把 A 换个名字再测。这些身体的顶点和形态映射不同，仍保持独立。描边只复用对应身体的几何：整人形态纹理 **26 份 / 25.06 MiB → 14 份 / 12.72 MiB**，不是每个演员都应该只有一份。

## 看起来和点起来是否仍然一样

- 每个材质代理保留自己的持久 `start/count`。颜色、描边、阴影和射线只在本次操作中切换共享范围，然后还原；衣柜、道具接触和遮挡在绘制之外读取[该代理自己的范围](../../src/mmdVrShowcase/mmdRuntime/modelDrawRange.ts)。紧凑拆分几何继续使用局部索引和自己的形态映射。
- 真实 WebGL2、固定 512×512、同一 renderer 依次执行旧／新准备路径。A、S 各 12 对图，含原衣全身、去描边、眨眼 0／0.5／1／0、隐藏和还原单件衣物、整人和单件衣物的地面投影。**24 对 RGBA 逐像素相同。** 正对照：A 和 S 从睁眼到完全闭眼分别有 6,895／4,550 个像素差超过 8/255；单件影子与无投影对照分别有 4,648／1,023 个像素超过此阈值。各自所有有效材质范围均用实际射线命中一块已知三角面，检查相邻材质不串面。A 仍有 20 个可操作衣柜槽、21 个表面范围（共 118,020 个索引）；S 为 37 槽、38 个范围。
- 构建后的准备页中，另一件真实 SDEF 模型走屏幕放置、物理开关、继续上次舞台，进入模拟 XR 后连续 8 帧两眼均提交演员网格。尚未验证 Quest 3S 实际峰值内存、系统回收行为或 FPS。

## 独立的 glTF 物件释放问题

旧清理只处理 `Mesh` 的几何和材质，会漏过 `Line`／`Points`，也未释放 skin 的骨架纹理或 `InstancedMesh` 自有的实例缓冲。修复后，收回、退出以及切房后才加载完成的物件，都按这一个已解码实例去重释放。

同一合成 glTF 含共用线材质／几何的两个节点、点云、蒙皮和 GPU 实例；通过正式物件加载路径放两个，再移除一个并清场。在预热了默认材质的桌面 renderer 上，空场基线是 0 个活缓冲、0 份几何、1 张纹理。旧版清场后为 **4／4／3**，新版为 **0／0／1**。移除第一个，两版的另一个都还显示原来的 7,092 个物件像素，没有像素差。另用[过期加载专项](../../src/mmdVrShowcase/stage/stageObjectDisposal.test.ts)确认未上场的组也走相同清理。

## 复查与下一步

用本地开发服务打开 [形态绘制对照](../../scripts/model-atlas-parity.html)，选择一个模型目录，分别选普通／拆分样本；[双实例分配探针](../../scripts/model-render-coverage.js)用 `testActor({duplicate:true})` 或传入真实表情名。两个高负载角色的旧版双实例用已有基线，勿并行启动多个浏览器。原始数值与测试计划保留在本机 `local-review/verification/atlas-parity/`、`morph-atlas/` 和 `model-coverage/`。

下一步若仍有内存压力，优先看 Quest 上**首次放置期间的峰值**与**站稳后的驻留**是否不同，并记录收回／回访后的基线。底色纹理在各实例之间仍独立，任何跨实例共享都需要另验换装、异步失败和释放所有权。
