## 回场：只留最近一次成功绑定的大身体动作

每次观看的小动作 LRU 仍是最多 4 份、合计 **4 MiB 源文件**。另加**一个**全观看共享的位置：身体动作在 **(4, 32] MiB** 内、实际成功绑定且主要是打包的骨骼／表情轨道，才保留只读的解析结果。按原 `File` 对象查找，每次回场仍创建模型、求值器和独立的物理世界。

- 0.8.6 把每 111 字节骨记录／23 字节表情记录转成 97／8 字节的定长数值数据。大槽只接受剩余非打包部分（包括文件头）≤512 KiB、轨道名总数 ≤4096 的文件，避免把大量相机帧、灯光或 IK 对象也留在内存。32 MiB 不是 JS 堆限制，首次解析、在场模型和 WASM 高水位不算在缓存内。
- 下一次成功绑定身体动作就替换或释放大槽，包括换成小动作或超限动作；表情／镜头的绑定不驱逐它。读失败、绑失败或被取消不替换上一次成功项。删去对应背包文件、退出观看分别按文件／全量清理，进行中的旧读取不能回填。单纯切房不清缓存；三角色轮流绑三支大舞也只留最后一支。
- 若回场报告仍为 `oversize`，身体文件超过新上限；`miss` 还需看期间是否换舞、换 File 或清库，或文件以非打包记录为主。没有理由仅凭一次未命中继续调高内存预算。

## 首开：保留放置就绪帧，给预热一个不依赖 idle 的机会

新角色手动放置成功、无警告且物理关，才在下一舞台帧**登记**预热；该帧不取模块。浏览器给空闲回调则先用，否则由约 1 秒后的普通任务尝试。两者共用一个请求；若正在加载或背包命令未结束，间隔 1 秒再核对。房间退休、清空、开物理或发生致命错误则放弃。导入、空场、失败、移动、自动回场均不会提前触发。定时器不是截止时限：页面暂停、操作系统和浏览器调度仍可能让用户先点到开关。旧版只登记一次无限期 idle 回调；`cold` 本身不能区分没登记、没有 idle 和回调恰逢繁忙。

预热只取物理入口及其同版本 JS/WASM；不会建后端、建世界、推进刚体或写入物理偏好。显式开启与进行中的预热共用 Promise，若遇预热失败则按需重试；失败不在后台循环请求。模块页级复用，只有各模型自己的世界随 runtime 释放。

**桌面对照。** 同一 Edge、同一 505 骨模型和 15.45 MiB VMD，冷／暖各一张新页，强制不派发任何 idle 回调。各在放置、绑舞、过一帧后等相同的 2 秒，再开→关→开。[探针](../../scripts/physics-toggle-probe.html)参数 `?startup=cold&idle=starved` 或 `?startup=warm&idle=starved`。冷首开 **174.6 ms**（模块 148.3 ms），暖首开 **21.6 ms**（`warmed`，模块低于计时分辨率）；再开分别为 6.1／8.9 ms。两页空载均无 Bullet 请求，首开前均零刚体／零 step，JS／WASM 各取一次，两次显式开启全程共建／销毁 2 个世界。

**舞台联调另测。** 本地开发版、Edge + IWER／软件绘制、合成 PMX 和同一大 VMD：空教室无 Bullet WASM 请求，用模拟控制器射线放下角色，继续抑制 idle。开物理时导出 `warmed`／模块 0.1 ms，全程只取一次 WASM。开着物理泳池往返回教室，导出 `body`／`hit`／`js`，动作任务 45 ms、`loadWallMs` 44.1 ms、绑定 0.3 ms，角色恢复播放。命中也可能在已完成的 Promise 上等待主线程调度，因此 `loadWallMs` 不一定接近零；这个模拟器的帧率和整房耗时不作头显预测。

这是把一次加载移到放置后，不是消除工作。启动模块时头显是否出现新的长帧、自然操作的首次开启是 `cold`／`warming`／`warmed`、稳定播放和拨衣手感，需要分别在 Quest 验证。
