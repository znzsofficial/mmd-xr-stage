# 性能：下一轮先修什么

**先定位礼拜堂首次开物理的长等待，再处理持续播放。** 目标是 Quest 稳定 72 FPS。11 月 19 日 16:39Z 的礼拜堂报告只有一次开物理，没有切换子阶段；`1abb982` 已补上计时。14:36Z 的教室报告可用来查回场，但教室关阴影、礼拜堂开阴影，不是版本 A/B。[原始条件与筛窗](./viewing-and-diagnostics.md#已有测量) · [下次一份 JSON 怎么测](./next-quest-export.md)

## 首次开物理

旧报告中首次开物理耗时 **12.631 秒**；首次从背包放下角色则是 **5.521 秒**（其中 `init-core` 3.183 秒）。这是两个不同操作。

**不用等头显就能做的第一件事**：在本机固定原版 PMX、VMD、步长和电源模式，分别记录新页面首次开启、同页关闭和再开。用[切换探针](../../scripts/physics-toggle-probe.html)复核姿态与渲染资源复用；分轮做冷／热对照，确认新报告能完整区分各段。桌面先验证假设，不能拿桌面最快一轮解释旧 Quest 的 12 秒。

收到新版 `physicsRebuilds[].work` 后，按耗时选改动：

| 哪一段长 | 含义与下一步 |
|---|---|
| `waitForSlotMs` | 切换在串行队列中等候；先查前一次任务和触发顺序。 |
| `bulletModuleMs` | 等动态模块及 Bullet JS/WASM 就绪，包含下载、初始化或等待已有请求。若首次远大于再开且主导总等待，才试角色放置后的低优先级预取；同时复测空场首帧和首次放置。 |
| `createBackendMs`、`evaluatorMs`、`bindAndSwapMs` | 分别查建后端、建求值器、还原绑定姿态／绑动作／换求值器。只优化占主导的阶段，验证动作不跳、缩放正确、失败可回滚。 |
| `publishUiMs` 或其余墙钟 | 查模型／材质列表刷新和未覆盖的等待。关闭时另有 `readModelMs`，失败可能有 `rollbackMs`。不要把未解释部分归给 Bullet。 |

子阶段按操作内的多个角色累加，**不再加到 `durationWallMs` 上**。首个原生播种帧可能在忙段结束之后；忙段、首个就绪帧和恢复稳定播放应分开看。

## 持续播放

礼拜堂空手、单角色、阴影开，物理关／开稳定窗口中位数 **61／34 FPS**；开物理时模型更新 13.56 ms，其中 `worldStepMs` 8.42 ms。先固定动作、机位、物理开，只切阴影。结合帧间隔、绘制量与模型 CPU 计时判断下一项做渲染侧还是求解侧；XR 回调间隔不是 GPU 耗时。

本地候选用[配对播放探针](../../scripts/paired-playback-probe.html)比较总更新、原生步进、慢帧和轨迹。保留有效接触和 PMX 关节，复核骨矩阵、蒙皮轨迹、暂停拨衣首触、移开回落及追踪恢复。单项计时变短而总耗时无稳定改善，不作为帧率收益。[已做的等价优化和隔离实验](./xr-runtime-performance.md)

## 回场与后续验收

- **回教室**：旧两区样本 2.669 秒中，恢复队列 2.612 秒，模型任务 1.839 秒，动作仅 10 ms。VMD 解析复用、PNG 透明度采样复用均已发布。后者桌面让贴图阶段 188.9→29.9 ms，但含上传的整个模型任务 501.3→510.4 ms，没有稳定缩短。下一项分查预上传和让步，看端到端时间。[条件与回归](./load-work-room-alpha.md)
- **校园三区**：教室↔草坪↔泳池已上线。待 Quest 同条件观察播放、过门等待及多次往返后的纹理／几何体数量；模拟 XR 已验角色和物件按区恢复。[两区旧基线和三区桌面对照](./campus-passage.md)
- **暂停休眠**尚未实现。先分别测衣摆静止、手靠近和实际触碰；首触不漏、收手回落、追踪恢复与 seek／循环通过，才试减少求解。地台、草坪各 15 分钟分别导出，不占礼拜堂短测时间。
