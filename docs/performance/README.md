## 下一里程碑：复杂角色开物理播舞

**本轮结果：**重角色开物理的持续慢帧中，有一笔大开销在 `rt.update` 之后：XR 每秒约 30 次查询手柄是否碰到模型。发布用 Bullet 的接触收集在缓冲区装不下时仍会返回完整数量；loader 原来总是先数一次、再遍历一次取值。现在直接填已有缓冲区，只在需要扩容时重读，撤手后仍读当步结果。[原生分段、配对与复现](./bullet-step-profile.md#090-重角色与触觉查询)。

首次筛查用桌面 CPU、1/60 秒一帧，一份 929 刚体、1,608 关节的原件每步 Bullet 中位约 **10.0 ms**，角色总更新中位约 **14.8 ms**。另一份面数更多、刚体更少的变体每步约 **1.2 ms**。变体只用来选样。后续的改动前后对照都用同一原件。具名样本见本机 `local-review/endfield-round/README.md`。以下是本轮采用的验收标准：

1. 用当前发布的 Bullet 在同一舞段复现慢步，区分关节求解、碰撞与骨骼回写。参考[原生步进分测](./bullet-step-profile.md)的方法；其中旧 WASM 的插桩和数值不可直接套到当前版本。
2. 只改可重复测到的主耗时。用重角色与普通角色各自做固定步长、机位、画风的交替前后对照，同时看角色总更新 P95 和实际可见 XR 回调间隔；局部变快只报告局部收益。
3. **收工条件：**重角色总更新的慢帧重复改善，普通角色没有可重复退化；同姿的尾根仍连在身上、裙摆仍响应接触，暂停、撤手、恢复播放正常。没有收益就保留基线。第一轮可全由本机完成，设备结果单列。

**另案保留：**一份 1,182 骨的原件在本机 WebGPU 超过 1,024 矩阵容量，但实际蒙皮只引用 920 根。若下一步要解决“放不上场”，候选是在 loader fork 中压紧绘制用骨矩阵表，保留 VMD、IK、Bullet 和接触查询的原骨编号。验收是从正式背包放置、双眼播舞、描边随动及收回；不能用它代替上述物理性能验收。[记录开关取舍](./viewing-and-diagnostics.md#要不要加记录开关)独立于两项工作。

## WebGPU 首次放置与切画风

把玩家点选到看到结果的等待与 GPU 每帧执行时间分开。用同一份穿衣 PMX 的两个独立背包条目，在正式舞台依次放人，再让一人切「仿终末地 → 原 MMD → 仿终末地」。放置窗口终点要求两眼已提交、应出现的演员都已绘制且布料驱动就绪；画风窗口在定格舞段、关物理时取首次符合所选画风的双眼提交，另记眼图复制完成时刻。GPU API 请求次数和对象数不代表驱动编译时间。

**布料。** 同一桌面 NVIDIA GPU、模拟 XR、每眼 240×240，各开一个冷页面对照 `fb4a7be` 和 `1563149`。首位需要布料和手部承托的演员并行准备两组管线，第二人及同设备重入复用编译结果。[实模控制器回放与资源回收](./gpu-cloth-lab.md#实际解算的内容)。

| 同脚本测量 | 第一人：原版 → 复用＋并行 | 第二人：原版 → 复用＋并行 |
|---|---:|---:|
| 新增布料管线请求 | 4 → 4 | 4 → 0 |
| 布料首个请求到最后完成的墙钟 | 1168 → 707 ms | 357 ms → 无请求 |
| 确认放置到两眼提交且布料就绪 | 1860 → 1126 ms | 736 → 470 ms |
| 期间最长跟踪回调间隔（含提交后的下一帧） | 565 → 361 ms | 294 → 239 ms |

第二人同时省去两次 `getCompilationInfo`；全部新增管线对象由 7 降至 3，剩两条 Three compute 和一条 render。可重复确认的是**相同管线没有再请求**。表中墙钟是每个固定提交各一次实测，包括 PMX、贴图、JS 调度和 GPU 排队，并非纯编译时间。在只加缓存、尚未并行的中间版本，也测到过加载时间反而更长；不用单次差值承诺 Quest 加速或持续帧率。对照脚本：[compile-stage.cjs](../../scripts/webgpu-actor/compile-stage.cjs)；本机两次完整记录汇总为 `local-review/verification/pipeline-compile/fb4a7be-02-vs-1563149.json`。

**再次切到已经画过的画风。** `1563149` 的仿终末地复切重新创建 17 条渲染管线和 28 个 shader module，WGSL 文本逐份与首切一致。给当前演员的画风绘制使用稳定的 Three `passId` 后，保留原材质、贴图与衣柜状态，Three 能复用之前的绘制对象。未用过的画风仍按需建立；改过透明混合或顶点节点则按新状态重建。双面透明材质的背面继续使用 r187 自己的 `backSide` pass，仍可能触发重建。两种后端对照见[技术栈](../xr-rendering-stack.md)。

| 实模双人同场，仅切第一人（每眼 240×240） | 原 MMD → 仿终末地 | 返回原 MMD | 再切仿终末地 |
|---|---:|---:|---:|
| 新 shader module / render pipeline | 28 / 17 | 0 / 0 | **0 / 0** |
| 扳机松开到正确画风的双眼提交 | 49.0 ms | 36.6 ms | **7.8 ms** |
| 扳机松开到同帧双眼复制完成 | 1431.0 ms | 42.4 ms | 12.5 ms |
| 最长跟踪回调间隔 | 47.8 ms | 34.3 ms | 6.1 ms |

`1563149` 复切提交为 60.4 ms，复切新版本为 7.8 ms，分别取各自一次桌面回放。首切依然需要编译，读回等待包含此前排队的工作；提交和读回都不是镜片呈现时间。固定姿势下，恢复 MMD、复切相对首次和同场未切演员均在两眼逐像素一致。另一名带实际脸影与三组衣料附图的演员，定格切回原色双眼残差均为零，续播仍是同一实例。详见本机 `local-review/verification/pipeline-compile/hot-pass-game-01/summary.json`。

## WebGPU 单人播舞

`ce972ce` 已发布布料驱动优化。桌面原生 GPU、模拟 XR，同一 505 骨演员和舞段，每次掌面采样上传 **32,320 → 13,504 字节**，布料驱动平均 CPU 时间 **0.135 → 0.108 ms**；实际回调间隔 P95 **7.4 → 7.6 ms**，未证实整帧提速。[对照条件与双手撤回结果](./gpu-cloth-lab.md#实际解算的内容)。

若继续追慢帧，建议先固定海站公园机位、眼图尺寸和灯光，分别测空场、原 MMD 单人、同演员换画风，再单独切树影。保持同段 VMD、衣着和物理设置，每步只改一项；用可重复的慢帧差异决定改演员还是布景。桌面对照可先做，Quest 实机回访未排期。

**分清 GPU 时间。** 正式 WebGPU XR 链接加 `&gpuTiming=1` 后，退出时导出的每个完整秒窗至多测末尾一帧。支持 `timestamp-query` 才会在原有 GPU pass 写时间戳；每次只异步读取一个小缓冲，不另画场景。`gpuFrameTimeMs` 标识采样的 XR 回调，`gpuPasses` 的各项是该帧的毫秒数：

- `clothMs` 是本帧实际执行的原生布料 compute pass 之和，`clothSteps` 是其中的步数；没有步进时耗时为 `null`。`threeComputeMs` 是 Three 自身的 compute pass（可含角色形态和手动摆姿裙片），和原生布料分开。
- `stereoSceneMs` 是主场景两个眼层的绘制 pass 之和；`stereoOutputMs` 是两个最终转色 pass 之和。r187 自带计时把同一对索引复制给两个眼层，不能直接读作双眼总和。采样只认独立索引和完整双眼；遇到分段场景绘制、缺眼或漏读，相应值为 `null`。有效的零差值可能来自设备时间戳量化。
- 独立阴影图、队列写入／等待、CPU、合成器未计入这些 GPU 分项。`status: unsupported` 表示设备未启用时间戳；`missed` 不补上一次值。窗口级 `modelUpdateCpuMs`、`physicsPoseWork`、`bulletStepWork` 和回调间隔仍是原有 CPU／帧节奏口径。

同一开关还会导出 `webgpuFirstUse`，无需设备支持 GPU 时间戳。`entry` 从本次入口开始，`model` 从运行时开始新建演员（含恢复布局）开始，`style` 从一次有效的画风切换开始。`toStereoSubmitWallMs` 截止到本次就绪后，同一可见跟踪回调内左右两层都提交了最终转色绘制；不证明演员在视野里或头显已呈现。只保留最近 120 条已完成记录。`maxTrackedIntervalMs` 包含提交后的第一个连续回调间隔，以覆盖提交时的阻塞；不跨失追、失焦计算，没有连续样本则为 `null`。

模型记录的 `loaderWallMs` 包含 loader 的 `loadTexturesWallMs` 子阶段，`attachWallMs` 单列同步挂接；画风记录的 `mapLoadWallMs` 是可选贴图读取、解码、包装的总墙钟，仅本次发起加载才有。`maps` 区分加载、复用进行中／已缓存的结果和跳过；`prepareStyleWallMs` 是同步准备节点调用，重复调用由 `repeatPrepareStyle` 标出。`threePipelineRequests` 与 `threePipelineCallWallMs` 是该时间段整个 Three 后端新发起的 render/compute 管线创建次数与调用返回前累计墙钟。入口计数从 renderer 初始化后开始，不含原生布料管线、不等待异步编译结束；同时放置或切画风的时间段可能重叠，不相加。

**可消除的重复提交候选。** 同一 505 骨、30,653 顶点 PMX 绑定上次测量的 VMD，在 1.408–3.400 秒间按 120 Hz 用实际 loader 求值，239/239 对相邻帧的全部 52 个浮点形态权重相同。loader 仍向记录器发出了 240 次覆盖全顶点的形态 compute 调用。此项为无物理的 CPU 验证；不能由次数推出 GPU 耗时。手动摆姿的裙片会直接改写同一输出缓冲，复用输出还必须区分这种写入和回到原姿的首帧。

**正式入口桌面实绘。** 同一摄影地台、固定视点、每眼实际 232×230、原生 GPU＋模拟 XR，6 个空场窗、7 个原 MMD 单人播舞窗均读到双眼场景和转色时间。演员的 1,205 帧观察里，1,137 帧的形态权重与前帧相同，仍调用 Three compute；3 个有布料步进的采样端点分别测到 **0.393、0.393、0.197 ms**。其余无步进窗不计入布料耗时。没有换算 Quest FPS，也未据此更改 loader 的形态输出寿命。

串行复测命令：`node scripts/webgpu-actor/game-floor-smoke.cjs "<原衣演员.pmx>" "<身体动作.vmd>" --gpu-timing`。`clothTiming` 分开报告有布料步进的采样帧与零步进帧；固定步频偶尔会使整个短测只采到零步进端点，这时保留双眼数据，布料时间缺样。

**海站空场：天空、远海和近海遮挡。** 原版在每只眼绘制两层完整球面，地平线下的天空被远海覆盖，地平线上方的远海片元全部丢弃。现在两者只画各自半球，保留原经纬分段密度；不透明海水排在普通不透明布景之后，让码头和建筑先写入深度。光照、波纹计算、分辨率与抗锯齿设置未降级。

桌面 NVIDIA GPU、模拟 XR、每层 652×652、关实时阴影。在同一场景交替切回原几何／顺序，每档每机位采 48 个跟踪帧。合计双眼场景与最终输出的四个 render pass，均值：喷泉公园 **0.262 → 0.206 ms**，向海 **0.284 → 0.265 ms**；两机位定格前后的最终双眼 RGB 各通道最大差都是 0。原始时间戳有量化，不把这些差额解释为整帧或 Quest FPS；本组不含演员。复核记录在本机 `local-review/coastal-pass-result.json`。

## 首次开物理

旧礼拜堂首次开物理耗时 **12.631 秒**，没有分段；同场首次从背包放下角色则是 **5.521 秒**（其中 `init-core` 3.183 秒）。`1abb982` 的教室记录能把这两种操作分开，且同一会话第二次开物理只需 134 ms。

**桌面刻意不派发 idle 回调**，同一 PMX／15.45 MiB VMD 的首开墙钟为 174.6 ms（按需）和 21.6 ms（放置后一秒定时任务已预热）。首开前两页都没有运行角色物理。头显上要核对放置后有无新顿挫，而不只看开关数字。[预热与回场诊断](./physics-warm-start.md) · [本地复核探针](../../scripts/physics-toggle-probe.html)

用 `physicsRebuilds[].work` 判断改动落在哪一段：

| 哪一段长 | 含义与下一步 |
|---|---|
| `waitForSlotMs` | 切换在串行队列中等候；先查前一次任务和触发顺序。 |
| `bulletModuleMs` | 等动态模块及 Bullet JS/WASM 就绪。若首次仍慢，查 `moduleAtFirstRequest` 判断没启动、正在预热还是已就绪；同时核对空场首帧及首次放置。 |
| `createBackendMs`、`evaluatorMs`、`bindAndSwapMs` | 分别查建后端、建求值器、还原绑定姿态／绑动作／换求值器。只优化占主导的阶段，验证动作不跳、缩放正确、失败可回滚。 |
| `publishUiMs` 或其余墙钟 | 查模型／材质列表刷新和未覆盖的等待。关闭时另有 `readModelMs`，失败可能有 `rollbackMs`。不要把未解释部分归给 Bullet。 |

子阶段按操作内的多个角色累加，**不再加到 `durationWallMs` 上**。首个原生播种帧可能在忙段结束之后；忙段、首个就绪帧和恢复稳定播放应分开看。

## 持续播放

11 月 20 日 14:43Z 教室阴影关，离开教室前的稳定播放窗物理关／开中位 **64／42 FPS**，开着回场后另计 45.5 FPS。旧礼拜堂阴影开为 61／34 FPS。这不是锁定条件的版本或阴影 A/B。缓存不改变求解器，预热不减少每帧步进；XR 回调间隔也不是 GPU 耗时。

**11 月 22 日复核后的取舍。** 离开教室前、单角色无阴影的 15 个正常物理播放窗口（68.99–84.16 秒，剔除含播种的窗），`backendMs` 中位 5.42 ms；其中原生 `worldStepMs` 5.04 ms，输入 0.05 ms，输出 0.24 ms。动画与 IK 另占 2.11 ms。关物理另有一次 981 ms 内等待 `modelFile.arrayBuffer()` 846 ms；现已[复用上场时读入的模型字节](./physics-toggle.md#关物理复用上场时的那一次读取)：页级合计 32 MiB，实模开关不增加读取，移除最后一位演员即释放。头显关物理总墙钟仍待复测。

**持续播放未证实提速。** [原生步进分测](./bullet-step-profile.md)：505 骨实模两轮均以约束求解为首（约 49%），其次是窄相派发（约 28%），AABB 更新加宽相配对约 16%。[主迭代行循环](./bullet-step-profile.md#主迭代行循环)已分账：48/48 窗关节行重于接触／摩擦行，准备里关节转换最贵。下一步看实际执行行数及 override 条件，不优先改[22 个停放体](./xr-runtime-performance.md#跳过重复运动学写入不采用)。桌面占比不外推到头显。

本地候选用[配对播放探针](../../scripts/paired-playback-probe.html)比较总更新、原生步进、慢帧和轨迹。保留有效接触和 PMX 关节，复核骨矩阵、蒙皮轨迹、暂停拨衣首触、移开回落及追踪恢复。单项计时变短而总耗时无稳定改善，不作为帧率收益。[已做的等价优化和隔离实验](./xr-runtime-performance.md)
