# 性能：下一轮先修什么

**首次开启和回场有了两条不同的线索。** 11 月 20 日 03:17Z 教室首次开物理，1493 ms 中有 1434 ms 等 Bullet 模块；泳池回教室 8815 ms 中，身体动作任务占 6207 ms。应分别验模块预热和动作恢复，不能用一次切换更快说明播放已到 72 FPS。[原始条件与筛窗](./viewing-and-diagnostics.md#已有测量) · [Quest 短测](./next-quest-export.md)

## 首次开物理

旧礼拜堂首次开物理耗时 **12.631 秒**，没有分段；同场首次从背包放下角色则是 **5.521 秒**（其中 `init-core` 3.183 秒）。`1abb982` 的教室记录能把这两种操作分开，且同一会话第二次开物理只需 134 ms。

**已实现放置后的空闲模块预热。** 本机同一 PMX/VMD 各一轮，冷开／预热后开分别为 143.2／6.9 ms；这是切换墙钟时间。模拟 XR 忙碌时仍可能报告 `cold`，走原按需路径。下一步看头显是否出现 `warmed`，以及放置后是否产生新的长帧。[预热与回场诊断](./physics-warm-start.md) · [本地复核探针](../../scripts/physics-toggle-probe.html)

用 `physicsRebuilds[].work` 判断改动落在哪一段：

| 哪一段长 | 含义与下一步 |
|---|---|
| `waitForSlotMs` | 切换在串行队列中等候；先查前一次任务和触发顺序。 |
| `bulletModuleMs` | 等动态模块及 Bullet JS/WASM 就绪。放置后的空闲预热已上线；若首次仍慢，先查 `moduleAtFirstRequest` 判断没启动、正在预热还是已就绪，并核对空场首帧及首次放置是否新增长帧。 |
| `createBackendMs`、`evaluatorMs`、`bindAndSwapMs` | 分别查建后端、建求值器、还原绑定姿态／绑动作／换求值器。只优化占主导的阶段，验证动作不跳、缩放正确、失败可回滚。 |
| `publishUiMs` 或其余墙钟 | 查模型／材质列表刷新和未覆盖的等待。关闭时另有 `readModelMs`，失败可能有 `rollbackMs`。不要把未解释部分归给 Bullet。 |

子阶段按操作内的多个角色累加，**不再加到 `durationWallMs` 上**。首个原生播种帧可能在忙段结束之后；忙段、首个就绪帧和恢复稳定播放应分开看。

## 持续播放

11 月 20 日教室阴影关，物理关／开为 **60／41 FPS**，开物理的 `worldStepMs` 为 6.96 ms。旧礼拜堂阴影开，分别为 **61／34 FPS** 和 8.42 ms。两景不是阴影开关实验。先固定动作、机位、物理开，只切阴影，再结合帧间隔、绘制量与模型 CPU 计时判断渲染侧与求解侧的成本；XR 回调间隔不是 GPU 耗时。

本地候选用[配对播放探针](../../scripts/paired-playback-probe.html)比较总更新、原生步进、慢帧和轨迹。保留有效接触和 PMX 关节，复核骨矩阵、蒙皮轨迹、暂停拨衣首触、移开回落及追踪恢复。单项计时变短而总耗时无稳定改善，不作为帧率收益。[已做的等价优化和隔离实验](./xr-runtime-performance.md)

## 回场与后续验收

- **回教室**：11 月 20 日从泳池回教室，动作 6207 ms，模型 1561 ms。前一天从草坪回教室，动作仅 10 ms，模型 1839 ms。两者都成功，但不能假定动作、缓存命中和绑定路径相同。下一份报告应先查动作子阶段，再考虑预上传和让步；已发布的 PNG 透明度采样复用仅证明贴图阶段变快。[条件与回归](./load-work-room-alpha.md)
- **校园三区**：教室↔草坪↔泳池已上线。待 Quest 同条件观察播放、过门等待及多次往返后的纹理／几何体数量；模拟 XR 已验角色和物件按区恢复。[两区旧基线和三区桌面对照](./campus-passage.md)
- **暂停休眠**尚未实现。先分别测衣摆静止、手靠近和实际触碰；首触不漏、收手回落、追踪恢复与 seek／循环通过，才试减少求解。地台、草坪各 15 分钟分别导出，不占礼拜堂短测时间。
