# 切体位的第一帧，以及衣物晃动时的遮挡检查

这是两条不同的 CPU 路径。前者只在开物理、手动摆姿时启用；后者在已配置角色工具，需要检查当前服装时运行。下列数据在桌面测得，不能相加，也不代表 Quest 的 FPS。

## 换姿后第一次看到裙形

基线 `dfc1c35`，同一原衣角色 A。先前会为整个腿部材质的所有三角面递归排序，建出完整的最近面查询树，哪怕最后只查很小的一片。现在仍在拟合时读取**完整的当帧腿面**，但只对查询确实经过的分支排序；稳定排序、分割轴、等距面的先后次序不变。后续访问新区域只用该次捕获的面，不会混入另一帧的腿姿。另在首次扫描衣层时按材质组标记已访问的顶点，同一个三角网边角不再反复计算；实际腿面、衣层及碰撞许可都未删减。

两版输入为相同的 121 帧连续原生 Bullet 轨迹。每条路径先预热两对，再做 12 对，交换先后；每次重新建立当前演员的衣料显示层。下表是**显示层建模 + 本次拟合 + 首次绘出几何**的 CPU 耗时中位数，未计读 PMX、姿势按钮到下一帧的等待、Bullet 步进或 GPU。

| 从普通站姿切到 | 旧版 → 新版 | 新版更快的配对 |
|---|---:|---:|
| 仰卧屈膝 | 76.09 → 61.34 ms | 11/12 |
| 仰卧分膝捧腿 | 67.64 → 50.01 ms | 11/12 |
| 仰卧抬腿 | 45.10 → 38.77 ms | 8/12 |

**是否把整笔开销推迟了？** 连同随后的 120 次衣面显示，三条路径累计 CPU 中位数分别为 822→745、489→464、603→592 ms（不含帧间还原）。抬腿的收益较小，首帧 P95 为 59.8→62.9 ms，没有尾部改善结论。首次拟合仍足以错过一帧。

**裙子有没有变形？** 同一时刻比较整套骨世界矩阵和各蒙皮位置缓冲：A 三种仰卧、抬腿转深跪和返站，共 605 帧完全相同；稀疏裙 B、多层裙 C 各五条路径再核对四个窗口。生产构建也通过实际「仰卧屈膝／仰卧分膝捧腿 → 保留姿势并返回 → 恢复原动作」确认两种新姿势都有外裙修正，返回站立后外裙位置属性恢复原值。未关闭上版的站姿减抖。

## 开着角色工具，原衣随物理晃动

衣物分块先算骨骼变换后的包围盒；以前每根相关骨都要变换八个角，现在直接取每个坐标轴上产生最小值、最大值的角，保留乘加次序。三个顶点都处在检查框**同一面外**时才跳过后续三角形精测。各块和三角面的扫描预算不变；旧姿态的覆盖图不能给新姿态作证。

同一角色默认站立，按 72 Hz 取得实际显示骨架；预热后为每个工况重放 64 帧，并重复最后一帧另作静止对照。桌面 CPU 毫秒／帧：

| 工况（衣物仍在动） | 遮挡检查中位，旧 → 新 | 含遮挡的整个角色附件更新中位，旧 → 新 |
|---|---:|---:|
| 未配置角色工具 | 不调用 | 0.001 → 0.001 |
| 已配置，选中角色但不显示附件 | 0.442 → 0.282 | 0.455 → 0.291 |
| 已安装附件，无支架 | 0.463 → 0.290 | 0.473 → 0.298 |
| 支架待命 | 0.461 → 0.307 | 0.494 → 0.332 |
| 支架运行 | 0.411 → 0.284 | 0.467 → 0.316 |

衣物真正不动时原本就能复用结果，未见可靠收益。五种工况 × 移动／静止，前后每帧覆盖像素与遮挡状态、支架位置、测量和交付结果相同。对这个模型，连续移动的 64 帧中有 63 帧都未能在姿态再次变化前完成验证，**本次优化没有把这些帧变成已验证**。固定末帧后两版在同一帧完成同一张部分覆盖图。生产屏幕实模从附件安装、横移到还原均可用；另在 WebGL 用实材质核对全盖、半盖两侧、移开后恢复。
