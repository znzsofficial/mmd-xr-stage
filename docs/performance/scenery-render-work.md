# 布景渲染：海站花园、小行星与庭院

## 海站公园空场：逐组隐藏对照

沿用 `9cab064` 生产制品，桌面硬件 WebGPU＋模拟 XR 实得 72 Hz，投影层每眼 1462×1462、阴影关。固定头姿与时钟，三个机位各自交替保留／隐藏一组布景，每组各 32 个双眼样本，每批单独预热。分开记录双眼主场景和最终转色。以下数字是**整组隐藏**时少掉的主场景 GPU 工作量，不能加总或当成可交付优化的收益：

- **长椅：**少画公园树木（树冠、木质部分、树影）约 0.42 ms，单藏叶簇约 0.28 ms；少画公园店面约 0.37 ms。
- **商店街：**少画公园店面约 0.63 ms（四个交替批次分别约 0.72／0.65／0.48／0.66 ms）；少画整组树木约 0.10 ms。
- **喷泉前：**少画公园店面约 0.18 ms、整组树木约 0.17 ms。三个机位没有测到隐藏喷泉水面、水柱与水花的可重复收益。天空与两层海面合计在三个机位的差值约 0.23–0.35 ms；尚未把各层分开归因。

随后按立面、临街展品和远楼记录真实几何包围盒。实绘时保守取两眼都用得上的连续索引范围；完整几何仍供碰撞和投影，店面仍在原有实体、贴图两批中提交。商店街固定机位的两批合计每眼从 **56,146 降到 9,458** 三角形。六处固定机位的最终双眼像素与同一制品强制全画一致；桌面 GPU 时差较小，没有稳定的整场提速证据。移动碰撞、Quest 合成器和在场演员不在这组 GPU 计时内。复现：`node local-review/park-isolation.cjs --shops`；原始隐藏对照和范围 A/B 分别留在同目录 `park-isolation.json` 与 `park-shop-pair.json`。

## 海站花园与小行星北台｜2026-11-28

**花园闪面。** 沿街花店的锯齿屋顶基座与竖窗、各店勒脚与角柱原有可见共面；铺地横纵镶条在路口也叠画。现在屋顶共用连续基座、竖窗接到基座顶，勒脚收住角柱的端部，铺地在同一平面分区共边。没有改相机近裁面或全景材质深度。两排花桶和桌架的交叉支腿也拉开了实际间距。

桌面硬件 WebGPU＋模拟 XR，两眼各 816×816，固定镜头、时钟与光线，只反转三角形绘制先后，不改变绕序。统计最终 RGB 任一通道差 ≥5/255 的像素：商店街原为左／右 **164／185**，修复后 **4／1**；横移 3 mm 并微转后，**248／245 → 1／1**。铺装在商店街、喷泉、步道、长椅和交叉口的静止及微动对照，左右眼逐通道零差。喷泉远望店面仍有 **15／15** 个主要在远楼阳台和檐口交线的像素，不能宣称整景没有任何边缘闪烁。屏幕 WebGL 复测入口：`node scripts/verify-harbour-park.cjs --depth`。本机回投证据：`local-review/park-depth-result.md`。

屏幕 WebGL 两个正式制品以相同 1250×696 画布、24 位深度、四个机位测中心和左右平移 4.5 cm。中心机位的店面反序差异：商店街 **105 → 28**，喷泉 **417 → 99**，步道 **60 → 32**，坐姿 **407 → 28** 像素；每次恢复正常顺序后均回到基准画面。这是冲突定位，不是正常播放时每帧闪烁的像素数。

**花园树冠。** 六棵树的 2,880 片叶簇仍在四个实例批次内；分棵连续排列，跳过**两眼都看不到**的尾段，回看时恢复，不把远树换成图片。叶簇的风动、深度和投影照旧。相同 WebGPU renderer、双眼各 816×816、冻结时钟，原顺序与候选交替，每种采 32 帧。三个机位、烘焙及实时阴影下，最终双眼与原版逐像素一致：

| 正常观看位置 | 每眼实际树冠三角形，旧 → 新 | 开实时阴影，全部绘制 pass 均值 | 关实时阴影，全部绘制 pass 均值 |
|---|---:|---:|---:|
| 喷泉 | 34,560 → 23,040 | 0.465 → 0.416 ms | 0.281 → 0.272 ms |
| 长椅近前 | 34,560 → 17,280 | 0.723 → 0.709 ms | 0.723 → 0.723 ms |
| 商店街 | 34,560 → 11,520 | 0.915 → 0.903 ms | 0.850 → 0.858 ms |

每眼仍是 4 次树冠绘制。减少的是无效几何提交；没有在每个机位都测到 GPU 提速。本机同帧双眼与原始时间戳：`local-review/screenshots/park-canopy-pair/`。

**两项引擎能力。** r187 在双眼分层输出中不能安全使用显式 `BundleGroup`；当前宿主也不提供 multiview 单遍绘制。[命令录制对照与源码位置](../xr-rendering-stack.md#静态布景-render-bundles-和双眼单遍绘制)。正式入口已有独立的[按需 GPU 分段计时](./README.md#webgpu-单人播舞)。

**北台星云。** 仍画原来的天空层与两套有距离的发光／尘埃纹理坐标，把壳面求交和经纬换算移到稍密的球面顶点上，沿经度缝按三角形本地 UV 展开；太阳边缘、出现中的流星仍逐像素绘制。没有新增离屏 pass，也没把星核或行星环降分辨率。相同 WebGPU 设备、双眼 816×816、原材质和新材质交替，每种 40 帧：北台空场双眼渲染 pass 总耗时中位 **0.459 → 0.328 ms**，P90 **0.524 → 0.393 ms**。定朝向横移 6 米、微转 0.0006 弧度、看经度缝、太阳和流星都采了最终眼图，99% 像素的 RGB 最大通道差 ≤1/255，观测最大差 7/255。这些计时是桌面 GPU 的绘制耗时，不包含 Quest 合成器或角色物理。本机证据：`local-review/nebula-pair.json`。

## 较早的 WebGL 实测

基线 `eea2217`。下列是两个生产构建的桌面 WebGL 实际提交；画布 1100×646、balanced、无演员、同机位。阴影开时包括方向光深度绘制。表中三角形不是可见像素，也不是 Quest 帧率。

|---|---|---:|---:|
| 星环大厅入口 | 关 | 62 → 47 | 47,332 → 47,332 |
| 双喜堂入口 | 开 | 43 → 43 | 257,268 → 246,964 |
| 礼拜堂入口 | 开 | 23 → 23 | 175,719 → 148,839 |

| 伞灯星 · 伞林全景 | 开 | 55 → 55 | 352,567 → 352,567 |

**星门。** 六扇门的门框、底座、门背各用一次实例绘制；可点击门面、门牌和悬停指示仍各自独立。侧面贴近一扇门时是 29→26 次，但合并包围球多送 1,612 个三角形；门背是 43→30 次。固定星仪角度，三个机位各 710,600 像素，有 13／2／1 个像素任一色道差超过 8/255。六个目的地分别用屏幕鼠标、模拟 XR 扳机来回；核对悬停、按住不提前进入、松开进入正确房间、返回大厅。

**庭院投影。** 相机仍画原轿杆、宴桌及凳脚。仅深度绘制对小截面的旋转件、圆盘和弯杆减少圆周分段，共享原顶点。花轿加两桌的投影从 44,054 降至 33,750 个三角形。默认入口、正厅、门口、桌脚近景的同帧对照没有大于 8/255 的色道差；近看桌面时有 1,671 个像素超过此阈值，最大差 28/255。礼拜堂柏树不减面，只跳过光源看不到的连续尾段：默认树冠深度提交 34,560→7,680。将光移到树边复核，候选树影与完整树影逐像素一致，关掉树木投影才有明显差异。在两景中央分别放入同一演员，单独撤去演员投影可观测到 7,683／11,682 个变亮像素，前后计数一致。已验证设置里开关阴影以及回到别景时释放资源。

**星球。** 赭砾、霜岬远档分别为 9,396、11,460 面，离月心 18 m 以内恢复原来的 15,904 面，退到 20.5 m 才换回。只切换渲染索引；接缝、极点、原近景、行走支撑与风道均保留。屏幕落地朝向各自地表时，单独绘制月壳与基线逐像素相同。原始网格到远档的表面偏差不超过 16 mm；18 m 切档点以天体居中，赭砾／霜岬各有 47／9 个剪影像素变化。模拟双眼以实际控制器乘 01、02 风道往返，去程和返程均只切一次，两眼在同一帧选同一档，落地和转头保持近档。两个远档额外占用 125,136 字节索引，随房间释放。

**菌圃。** 把不透明的茎冠和发亮菌褶按 33 个林片排在原有两个索引缓冲中；每眼只裁掉自己视锥外的连续首尾，中间不能省就照画。半透明伞缘不重排。合影机位仅这两批从 98,624 降至 59,536 面，其余整帧差来自远月。屏幕合影与全景的静态菌圃 RGB 各通道最大差 1/255，林下和苗圃零差。模拟 XR 实际乘风到站转头，60 份眼图在相同姿态下比较裁剪和强制全画的菌伞、菌褶、伞缘，RGB 最大差 0。屏幕另验导览、步行、滚轮缩放、绕看、菌圃放置原衣演员和跨岛返程。

**能否说帧率提高？** 另用同一个桌面 WebGL 上下文固定机位，每组预热后做 16 对、每窗 12 次完整绘制，交替先后。开阴影的大厅入口，原独立静件与实例版本的 GPU 窗中位为 0.156→0.126 ms；北台仅切换两个远月索引，0.305→0.328 ms，未见稳定收益。菌圃、树影和家具均可确认少提交三角形，不把桌面的小差额换算成 Quest FPS。真机复测用同一画质、机位、阴影；先空场，再放同一角色并关物理，最后才单独开启角色物理。
