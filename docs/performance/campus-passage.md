# 教室—草坪连廊：播放与过门分开测

**现已连通教室↔草坪↔泳池。** 空草坪没有继续跑教室角色的 Bullet；11 月 19 日 14:36Z 的[两区成功回场](./viewing-and-diagnostics.md#已有测量)为 2.669 秒，主要在恢复队列。三区的模拟 XR 摇杆往返已验证：教室留一个播放中且开物理的角色，泳池放一件物件，草坪为空。回泳池恢复物件、回教室恢复角色和舞蹈；JSON 记录两次成功回场。新增区域的 Quest 帧率与过门等待尚待实机。下表为旧两区试点基准。

## 固定教室机位

Edge / SwiftShader，640×480，相同合成 PMX、循环 VMD、真实 Bullet 开启，默认教室机位。保存上线前的 `6a25403` 制品和试点制品，独立浏览器依次跑旧、新、新、旧；预热 24 帧，每轮 3 个 45 帧窗口。以下为各窗口的中位回调间隔范围，不是 GPU 耗时。

| 指标 | 独立教室 | 两区试点 |
|---|---:|---:|
| 每帧绘制调用 | 17 | 17 |
| 每帧绘制三角形 | 46,392 | 47,520 |
| 窗口 P50 | 42.4–48.5 ms | 42.4–48.4 ms |
| 在教室常规机位请求草坪三张图片 | 0 | 0 |

内置远景和廊架增加约 2.4% 三角形。小型合成角色、软件渲染和短窗口只用于此次对照，不能代表用户模型或实际头显帧率，也不证明这次改动提高了动作播放性能。

## 走廊交界

**草坪接泳池前后**：`e831225` 与三区生产构建，Edge/SwiftShader、640×480、同一合成 PMX/VMD、物理开、固定默认机位。每景独立浏览器按旧／新／新／旧，预热 28 帧，每轮 3 个 45 帧窗口。泳池从 13 次绘制／37,250 三角变为 15 次／35,212 三角（实时秒针和图集标牌各一批）；窗口 P50 旧 24.1–30.2、新 23.8–24.2 ms，P95 旧 24.3–48.5、新 25.0–40.6 ms。草坪从 11／54,491 变为 12／52,096。没有在泳池加载草坪的三张全景贴图。短时软件渲染未见稳定慢帧回退，但不能算 Quest 提速。模拟 XR 远端落点、回区动作恢复通过；重复过门是否随观看时间增长，仍看真实头显长测。

生产构建、桌面软件 WebGL、空场 960×700、先去连廊机位再跨界。发出切换后记录前十次屏幕 RAF，第一次去／回的最长间隔 309／317 ms，第二次 327／386 ms；这不是网络耗时或精确的 CPU 忙段。模拟 XR 另用左摇杆实走出门、转弯和返回，教室中角色与循环 VMD 已加载，草坪为空；两次跨界与恢复窗口的最长回调间隔 291／310 ms。确认草坪不挂载教室、在场角色从 1 到 0，回教室恢复为 1 且继续播放。实际经过时间受角色重新载入、设备与缓存影响。
