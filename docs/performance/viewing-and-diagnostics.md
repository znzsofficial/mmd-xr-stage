## 放置耗时：从松开扳机开始算

**返回已有角色的布景**单独看 `roomRestores[]`。`entryToVisibleFrameMs` 从切景请求到完成布局恢复后观察到的首个可见 XR 帧回调；分为开始队列前、执行队列到布景就绪、就绪到回调三段。`taskWallMs` 按角色／物件／身体及表情动作汇总，`modelWork` 记录各模型解析、贴图、预上传等阶段。子阶段已包含在总量内，不重复相加。仅统计带已保存资产的切景，放弃的切景不算成功，不导出私有文件名。它与 `placements[].confirmToReadyFrameMs` 是不同的计时，不是显示器实际呈现或 GPU 耗时。

**材质贴图读回对照（桌面 Chromium）**：在 `scripts/material-load-probe.html` 选择一个本地原版 PMX 和配套图片，改前、改后各新建 5 次 loader。21 个材质的测试角色每次整图 `getImageData` 从 19 次 / 304 MiB 降至 3 次 / 48 MiB（累计返回字节，不是显存峰值）。`load-textures` 中位数从 626.3 ms 降到 239.7 ms；21 项材质的透明模式、alphaTest、depthWrite 和贴图尺寸签名一致，零贴图告警。计时不含 GPU 上传和等待 XR 帧，不能据此外推遗庭报告的 1.395 秒会缩短多少。

报告的 `startup.firstVisibleXrFrameMs` 从打开本次 XR 覆盖层开始，到首个可见 XR 回调。`firstFrameAfterAssetsReadyMs` 是模型/物件列表已就绪且队列不再运行时的首个可见帧回调；都不是 GPU 完成提交的时间。约一秒的 `windows` 记录实际 `scenery` 选择。

从空场进入时，第二个启动字段会包含人在场内挑选位置的时间；不放任何模型／物件时保持 `null`。单独看 `placements[].confirmToReadyFrameMs`：从确认落点到命令完成后观察到的首个可见 XR 回调。`selectToPointMs` 还包括瞄准地面所花的时间；`moved` 区分移动已有实例和首次／再次取出。保留最近 120 条已观察到的成功记录，不含模型名、坐标或文件路径。

背包取出新建的角色实例还会记录 `modelWork`：`loaderWallMs` 是整个 loader Promise（读文件、解析、组网格和贴图）的耗时；`textureCount` 是预上传的唯一贴图数，`initTextureCpuMs` / `maxInitTextureCpuMs` 是同步 `initTexture` 调用的总耗时／单次最大值；`yieldWallMs` 是每张贴图后让出主线程直到恢复的实测总时间，含浏览器调度与同期渲染；`compileAsyncWallMs` 是预编译调用到返回的耗时，不支持时为 `null`。它们不代表纯 GPU 时间，也不覆盖整个确认流程。移动、GLB 和旧版本报告不含 `modelWork`。

自 `e0060ba` 起，`modelWork.loaderStagesMs` 提供七段互不重叠的耗时（毫秒），依次为 `read-bytes`、`init-core`、`parse-only`、`create-mesh`、`load-textures`、`material-metadata`、`assemble-model`。它们已包含在 `loaderWallMs` 内，不能再加到放置总耗时上。`load-textures` 包括材质贴图的应用过程，不是纯解码；`initTextureCpuMs` 测的是 loader 返回之后的预上传调用。

若真机多次显示让步时间占比较高、单张上传调用较短，再比较不同上传批次，同时检查确认延迟和最慢帧。若 loader 占主导，再细分解析、网格组装和贴图解码。若角色已就绪、播放时才卡，则先用相同动作对照物理开关和布景，不按首载问题处理。

## 播放帧率：对照整场和分段记录

`windows[].bulletStepWork` 把后端内部每次成功调用拆成三段：`feedMs`（检查／上传世界、同步刚体输入，含重置时播种）、`worldStepMs`（调用原生 `world_step`）、`outputsMs`（读动态刚体与转回局部骨骼坐标）。三项均按该窗口 `steps` 次后端调用求平均；其中 `seedOnly` 次只播种，不推进，原生步进记零。`steps` **不是实际执行的 Bullet 子步数**，现有 ABI 不提供该值。三项均包含在原来的 `backendMs` 所测路径内；外层手部映射／保护等包装另占时间。两处的分母可能因为无有效骨骼输出而不同。停止物理无样本时省略，报告不记录模型或骨骼名。

新版的 `windows[].physicsPoseWork` 只统计完成外部物理结果应用的模型求值。`evaluations` 是该窗口计入的模型次数；另四项是**每模型每次求值**的平均毫秒数：`animationIkMs`（求值开始到物理准备，包括动画、附加变换与 IK）、`prepareMs`（准备骨骼输入和输出缓冲）、`backendMs`（后端步进，含控制器／手部包装和刚体读写）、`writeBackMs`（处理结果并写入骨骼）。不包含步进之后的显示滤波、最终渲染同步及整帧其他 CPU/GPU 工作。`modelUpdateCpuMs` 仍是本次舞台更新内所有模型的总耗时的窗口平均；不要把两个不同分母的指标相加。没有完成的物理样本时该字段省略。

`physicsRebuilds[]` 记录同场景已结束的物理忙段，至多最近 64 次。当前日常入口是开关角色物理；旧版还有同组互撞重建。`requestedEnabled` 是开始时请求的状态，`success` 是忙段结束时是否无物理错误；`startWallMs` 从本次录制开始按墙钟计，`durationWallMs` 到忙段解除为止，不含其后恢复稳定帧率所用时间。切景或退出时未完成的段不计。窗口的 `elapsedMs` 则累积有效可见间隔，不能按数字与墙钟硬对齐。

`callbackIntervalMs` 提供平均值、最慢值和 P50/P95/P99（0.25 ms 分桶上界）；会话可见期间的长卡顿也参加统计，但进场及可见性变化后的第一段间隔不计。`overBudgetFraction` 为超过当时 session 实际 Hz 对应帧周期的比例，严格超预算会受到微小时序抖动影响；`overOneAndHalfBudgetsFraction` 单独统计超过 1.5 个周期的比例。两者都不是合成器丢帧数。刷新率未报告的帧不参与分母。

`windows` 按约一秒记录模型更新 CPU、舞台/物理开关、实际刷新率、图层大小与绘制计数，最多保留最近 1800 个样本；分布及最慢帧覆盖整场。模型 CPU 不代表 GPU 耗时。

`windows[].heldToy` 只表示**玩家**在采样瞬间手持的[目录道具 ID](../../src/mmdVrShowcase/play/propCatalog.ts)（如 `bubbles`、`wand`）。上文「空手」指 `heldToy: null`：道具仍可能由角色腕持，或装在支架上。此字段不能证明没有道具接触，也不记录电机档位、扣键或持物时长。

## 观看与调整

- 观看条提供播放/暂停、进度（有动作时）、场景、背包、更多和退出。选中已放置资产时，用目标旁的工具操作，完成后回到观看条。
- 「更多」分玩家／角色／环境，诊断在「环境」中；模型与材质详情从目标旁进入。[现行操作](../gameplay/vr-controls.md) · [设置清查与整改](../gameplay/settings-audit.md)。
- 选中可见角色后，「摆姿势」可锁脚拖腕；「互动」下方可预览胸型和初始乳量。「身体观察」直接打开四部位图；「互动 → 插入」可调游戏受孕率、看杆位和容量。记录事件时区分发出请求、实际有留存的交付，以及左图出现融合或散开的时刻。旋转或定格示意图不影响测量和判定。报告没有这些视图的逐项计时；首开顿挫、回访和双眼可读性需注明当时操作。
- 加载失败报告与物理错误独立于面板展开状态。物理异常可点击查看完整分页详情，不会因为收起面板而消失。
- 右手 B 键或“召回菜单”将 HUD 放到当前头部前方；重置视图后也重新定位。跟随开关主要更新朝向，不代表面板持续黏在视线上。

## 诊断值的含义

从调整面板打开「画质诊断」。数据按来源区分：

| 数据 | 来源与含义 |
|---|---|
| 进入时请求 | 本次创建渲染器时的 AA 和刷新率策略；未开启实验覆盖的倍率/注视点参数显示“运行时默认” |
| 会话刷新率 | `XRSession.frameRate`，不是所选预设中的目标值 |
| 回调 FPS / 毫秒 | 一秒窗口内的渲染回调频率与平均回调间隔，不是 GPU 渲染耗时，也不是合成器提交率 |
| 图层类型与总尺寸 | 当前 `XRProjectionLayer` 的 texture 尺寸或 `XRWebGLLayer` 的 framebuffer 尺寸，不冒充单眼分辨率 |
| 图层报告 AA | 仅显示 `XRWebGLLayer.antialias`；Projection 图层没有这个字段时显示“未报告” |
| 目标 samples | 当前 XR 渲染目标的 Three.js samples 配置，不是驱动实际采样数实测；普通离屏目标不计入 |
| 注视点强度 | 当前图层的 `fixedFoveation` 报告值；浏览器不暴露时显示“未报告” |
| 渲染调用 / 三角形 | 采样时 `renderer.info.render` 中上次渲染的计数，不是 GPU 时间 |
| 纹理 / 几何体 | `renderer.info.memory` 跟踪的对象数量，不是显存字节数 |
| 模型更新 CPU 平均 / 峰值 | `runtime.update()` 调用的墙钟耗时窗口，包含模型动画/物理/材质同步，不含全部 UI、渲染提交与 GPU 执行 |

会话不可见或采样出现长间断时重置 FPS 窗口。退出时清除诊断数据，不在下一次会话显示旧读数。

准备页的自动刷新率仅显示“自动高/中/低档”，不承诺固定 Hz。AA、framebuffer 倍率等创建时参数需要退出再进入才能应用。
