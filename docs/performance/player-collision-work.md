# 普通行走：减少经过新地面时的碰撞查询工作

玩家附近约一米的三角形会重复用于挡墙、地面、头顶和跳跃查询。旧版每次换到下一块区域，重新创建一批对象并用 `Array.from(typedArray.subarray(...))` 为每个三角形分配顶点数组；已在世界坐标建模的房间仍逐顶点乘单位矩阵。

[`solidColumns.ts`](../../src/mmdVrShowcase/movement/solidColumns.ts) 现在就地重填顶点，并只在**精确单位变换**时跳过矩阵乘法。平移、旋转、缩放及实例变换仍照常计算。扫描只看本次填入的部分；离开高密区域最多留 2048 个备用槽，换房或对象变化时清空。四面裁切、台阶高度、玩家宽度、重力、放置射线和角色 Bullet 均未放宽。

## 配对结果

运行 `node scripts/bench-player-columns.mjs`。默认从 Git 取 `34beed9` 的查询实现，新旧共用同一版 Three、同样的房间网格、路径和脚高。每步约 4.5 厘米，路径也故意穿过家具；逐点比较 `floor / ceiling / blocked`，再测 5 组预热、20 组轮换先后的配对。下表为本机 Node 26.12.1 **一整圈列查询的中位毫秒数**，不计场景绘制、加载、物理或头显帧率。

| 网格 | 每圈查询数 | 旧 → 新（ms） | 新版较快的配对 |
|---|---:|---:|---:|
| 暮灯套房的实物网格 | 453 | 54.18 → 37.47 | 20/20 |
| 月庭私汤的实物网格 | 571 | 71.58 → 43.47 | 20/20 |
| 教室 16 套桌椅的实例化框架，另加旋转且非均匀缩放的箱体 | 765 | 33.34 → 17.95 | 20/20 |

三条路线全部 **1789 个查询点**的三项输出逐值一致。已验薄墙、低顶起跳、台箱着陆、脚下物件移动触发失效及新景双人落点。这个改动针对普通行走，不用于解释站定看舞时的帧率。

## 给下一次头显导出做的预演

用 Edge 模拟 Quest 跑产品舞台：新开教室、扳机放合成 PMX、绑 VMD 播放、开／关物理、去泳池再回教室、正常退出下载 JSON。一次观测中，首次开物理报告 `warmed`，等模块约 0.1 ms，忙段 56 ms，全会话物理 WASM 只请求一次。返回教室成功，身体动作缓存为 `hit`，走 `wasm-adapter`，绑定约 0.2 ms；角色和播放都恢复。合成素材与软件渲染不复现旧真机那次 6.2 秒的动作等待，此处验证的是导出能区分这几类等待。真机操作见[最短一趟](./next-quest-export.md)。
