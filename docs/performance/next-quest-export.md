# 下次 Quest 短测：礼拜堂开两次物理，导出一份 JSON

[线上舞台](https://mmd-xr-stage.pages.dev) · [带切换分段计时的固定版 `1abb982`](https://e30a429d.mmd-xr-stage.pages.dev)。上次在礼拜堂第一次开物理等了 12.631 秒；旧报告只有总时间。这次要知道**第一次慢在哪一步，第二次还慢不慢**。

## 只做这一趟就够了

1. 下次自然进场时，在新打开的页面导入原来那一个角色和同一段循环 VMD，去**晨光礼拜堂**。先不开物理，让角色跳起来。尽量沿用上次的画质和阴影开，空手、固定机位；不用强设 120 Hz 或开启详细调试。
2. 在 **B → 更多 → 角色** 依次**开 → 关 → 再开**。每次等切换完成，看到动作继续几秒再操作。第一步之前别在别的布景先开物理，否则这不是本页的首次开启。
3. **正常退出 VR → 准备页「导出上次 VR 性能记录（JSON）」**。再次进入 VR、刷新或关页之前下载。只需 JSON 和一句话：`第一次开___；第二次开___；恢复后动作___。` 无需私有模型、视频，也不用走校园连廊。

## 有时间再做

- **礼拜堂播放帧率**：可以接在第二次开物理之后。同一机位保持物理开，在「环境」只切阴影，开／关各稳定播放约 30 秒；收起菜单、空手，留一句哪段转头更顺。开关顺序写明即可。
- **校园三区**：另一次游玩再测。教室留一个正在播放的角色，去空草坪，穿廊架到泳池，再经草坪回教室，等角色继续跳。若要查资源增长，在相同布局下多往返几次，单独导出这次会话。两区旧报告已收到，不必专门复刻。
- 握姿、天空、手追受压和暂停拨衣以目视、手感为准。没有哪个环节要求在本次短测一起完成；15 分钟长测另日分场导出。

## 收到报告后怎么读

- `physicsRebuilds[]` 筛 `scenery: chapel`、`success: true`；比较两条 `requestedEnabled: true`，中间那条是关闭。先比 `durationWallMs`，再看 `work` 子阶段。少了一次或缺 `work` 就标缺样。[字段及下一步](./README.md#首次开物理)
- 播放从 `windows[]` 筛同场、单角色、`playing: true`、空手、同物理状态的稳定窗，按 `shadows` 分组。开物理时要求实际步进，排除起播、切换和播种；比较窗口 FPS、`modelUpdateCpuMs`、`bulletStepWork.worldStepMs`。全场 P95 不是分段值。
- 回场只看 `roomRestores[]` 中目标明确且成功的事件。先拆 `preQueueMs`、`queueToReadyMs`、`readyToFrameMs`，队列慢才拆 `taskWallMs` 和 `modelWork`。首次从背包放置另看 `placements[].confirmToReadyFrameMs`。原始 JSON 留在本机即可。
