# 下次 Quest 短测：放置后开物理，再回教室一次

[线上舞台](https://mmd-xr-stage.pages.dev)。11 月 20 日教室报告已经收到：首开 1493 ms 中有 1434 ms 在等模块，回教室 8815 ms 中身体动作占 6207 ms。下一份报告重点看**角色放置后模块是否已经准备好、回场动作慢在哪里**。[首次开启与回场的工程对照](./physics-warm-start.md)

## 只做这一趟就够了

1. 在**新打开的页面**进教室，物理关，手动放下上次的角色并绑定同一支舞。按平时习惯看几秒，留意放好后是否顿了一下。沿用原画质、阴影关；不用强设 120 Hz 或打开详细调试。
2. 在 **B → 更多 → 角色** 开物理，等继续播放，再关。保留角色与动作，去泳池，再回教室一次。不用走完整条校园路线，通过场景菜单就行。
3. 看到角色恢复后，**正常退出 VR → 准备页「导出上次 VR 性能记录（JSON）」**。再次进入 VR、刷新或关页前下载。只需 JSON 和一句话：`放好后___；第一次开___；回教室___。`

## 有时间再做

- **礼拜堂播放帧率**：另日同一礼拜堂机位保持物理开，在「环境」只切阴影，开／关各稳定播放约 30 秒；收起菜单、空手，留一句哪段转头更顺。开关顺序写明即可。
- **校园三区**：另一次游玩再测。教室留一个正在播放的角色，去空草坪，穿廊架到泳池，再经草坪回教室，等角色继续跳。若要查资源增长，在相同布局下多往返几次，单独导出这次会话。两区旧报告已收到，不必专门复刻。
- 握姿、天空、手追受压和暂停拨衣以目视、手感为准。没有哪个环节要求在本次短测一起完成；15 分钟长测另日分场导出。

## 收到报告后怎么读

- `physicsRebuilds[]` 筛教室成功开启事件。先看 `work.moduleAtFirstRequest` 为 `cold`、`warming` 还是 `warmed`，再看 `work.bulletModuleMs` 和 `durationWallMs`，并核对空场首帧及首次放置时间。[字段及下一步](./physics-warm-start.md)
- 播放从 `windows[]` 筛同场、单角色、`playing: true`、空手、同物理状态的稳定窗，按 `shadows` 分组。开物理时要求实际步进，排除起播、切换和播种；比较窗口 FPS、`modelUpdateCpuMs`、`bulletStepWork.worldStepMs`。全场 P95 不是分段值。
- 回场只看 `roomRestores[]` 中目标明确且成功的事件。若 `taskWallMs.body` 长，查 `motionWork[]` 的 `cache`、`evaluator`、`loadWallMs` 和 `setAnimationMs`。这些分项已在队列总时间里，不再相加。原始 JSON 留在本机即可。
